1. เริ่มต้นใช้งานและภาพรวมหน้าจอ (UI Anatomy)

ระบบ MyLog ได้รับการออกแบบให้ทำงานบนเว็บเบราว์เซอร์ผ่านเครือข่าย Intranet ภายในองค์กร 100% โดยไม่เชื่อมต่ออินเทอร์เน็ตภายนอก มีมาตรการความปลอดภัยสูงสุดด้วย Path Traversal Protection (ป้องกันการเจาะเข้าถึงไฟล์นอกเหนือจาก Whitelist ที่ได้รับอนุญาต) และ Zero-RAM File Streaming เพื่อป้องกันปัญหาหน่วยความจำเซิร์ฟเวอร์เต็มเมื่ออ่านไฟล์ขนาดใหญ่หลายร้อยเมกะไบต์

องค์ประกอบสำคัญบนหน้าจอ:

  • แถบด้านบน (Top Navigation Bar)
    แสดงชื่อระบบ MyLog, กล่องระบุเส้นทางปัจจุบัน (Location Breadcrumb), ปุ่มสลับธีม สว่าง/มืด (Dark/Light Mode), ปุ่มรีเฟรช และปุ่ม 📖 คู่มือการใช้งาน
  • แถบควบคุมด้านซ้าย (Left Sidebar)
    สวิตช์เลือกโหมดการทำงาน 3 รูปแบบ: Local, Cluster / LB และ Remote พร้อมแผนผังต้นไม้โฟลเดอร์ (Folder Tree)
  • พื้นที่ตารางจัดการไฟล์ (File Browser Panel)
    แสดงรายการไฟล์ Log พร้อมข้อมูลขนาดไฟล์ วันที่แก้ไขล่าสุด และปุ่มคำสั่งด่วน: Open (เปิดอ่าน), Tail (สตรีมสด Real-time) และ Download (ดาวน์โหลด)
  • แถบเครื่องมือค้นหาและดาวน์โหลด (File Tools)
    ประกอบด้วยช่องค้นหาชื่อไฟล์, ตัวกรอง .log only, ปุ่ม 🔍 Search in folder (ค้นหาข้อความทั้งโฟลเดอร์) และปุ่ม ⬇ Download ZIP
💡 ทริคการปรับขนาดตัวอักษรและมุมมอง
คุณสามารถปรับตัวอักษรให้อ่านง่ายขึ้นได้ที่ปุ่ม A- และ A+ บนแถบเครื่องมือ รวมถึงสามารถสลับสวิตช์ Word wrap เมื่อต้องการดู Log แบบตัดบรรทัดพอดีหน้าจอ หรือดูแบบ Terminal แนวกว้าง

2. เจาะลึก 3 โหมดการทำงาน (Local / Remote / Cluster)

MyLog มีสถาปัตยกรรมที่ยืดหยุ่น รองรับการเชื่อมต่อแหล่งที่มาของ Log ได้ 3 รูปแบบหลัก เพื่อตอบสนองการทำงานของทีมงานในทุกระดับ:

โหมดการทำงาน ลักษณะการทำงาน กรณีการใช้งานที่เหมาะสม
💻 Local Mode อ่านไฟล์ Log บนเครื่องเซิร์ฟเวอร์ที่ติดตั้ง MyLog โดยตรง หรืออ่านผ่าน Windows Network Share (UNC Path เช่น \192.168.1.10Logs) ความเร็วในการโหลดสูงที่สุด เหมาะสำหรับเซิร์ฟเวอร์เดี่ยว (Single Server) หรือโฟลเดอร์แชร์ในวงแลนเดียวกัน
🌐 Remote Mode (Gateway) เชื่อมต่อไปยัง REST API Gateway ของสภาพแวดล้อม SIT หรือ UAT ดึงรายการโปรเจกต์และไฟล์ Log มาแสดงผลโดยไม่ต้องรีโมต ทีมผู้ใช้ที่ไม่ได้รับสิทธิ์ VPN ข้ามวงเครือข่าย หรือต้องการตรวจสอบ Log ของสภาพแวดล้อมทดสอบจากจุดเดียว
🔀 Cluster / LB Mode รวมศูนย์เครื่องแม่ข่ายหลายเครื่องที่ทำงานร่วมกันหลัง Load Balancer (เช่น Node 1: 192.168.1.10 และ Node 2: 192.168.1.11) ระบบงานสำคัญระดับธนาคารที่มีการกระจายโหลดหรือทำ High Availability (HA) เพื่อสืบสวนปัญหาที่กระจายข้ามเครื่อง
🛡️ กลไก Fault-Tolerant Probing ในระบบ Cluster
หากโหนดใดโหนดหนึ่งใน Cluster ขัดข้อง ชัตดาวน์ หรือเน็ตเวิร์กหลุด (Offline) ระบบ MyLog จะตรวจจับภายใน 2 วินาที และจะทำงานต่อไปโดยนำ Log จากโหนดที่เหลืออยู่มาแสดงผลอย่างต่อเนื่อง หน้าจอจะไม่ค้างหรือ Error และเมื่อโหนดที่ดับกลับมาออนไลน์ สถานะจะเปลี่ยนเป็น Online สีเขียวให้อัตโนมัติ

3. การดู Log ในระบบ Cluster (Timeline vs Concat)

เมื่อเลือกเปิดไฟล์ Log ในโหมด Cluster ผู้ใช้จะสามารถเลือกรูปแบบการจัดเรียงข้อความ Log จากทุกโหนดได้ 2 รูปแบบหลัก ผ่านปุ่ม Pill Switcher ด้านบน:

เปรียบเทียบข้อดีของแต่ละมุมมอง:

มุมมอง (View Mode) การจัดเรียงเนื้อหา การใช้งานที่แนะนำ
📑 All Nodes (ต่อกัน / Concat) นำ Log ของ Node 1 ทั้งหมดตั้งแต่ต้นจนจบ แล้วตามด้วย Log ของ Node 2 ทั้งหมด มีเส้นคั่น === Node: [NodeName] === ระบุชัดเจน เหมาะสำหรับผู้ใช้ที่ต้องการอ่าน Log ทีละเครื่องแบบต่อเนื่อง ไม่ต้องการให้บรรทัดของแต่ละเครื่องสลับไปมาให้อ่านสับสน
🌐 All Nodes (Timeline) ดึงบรรทัดจากทุกเครื่องมารวมกัน แล้วจัดเรียงตาม Timestamp เปรียบเสมือนเห็นภาพรวมของทั้งระบบพร้อมกันในวินาทีนั้น เหมาะสำหรับสืบสวนปัญหาการกระจายโหลด (Load Balancing) หรือการทำ Failover เมื่อต้องการดูว่าเครื่องไหนตอบสนองก่อนหรือหลัง
💻 เฉพาะเจาะจง Node กรองแสดงผลเฉพาะ Log ของเครื่องแม่ข่ายเครื่องนั้นๆ เพียงเครื่องเดียว เมื่อทราบแน่ชัดแล้วว่า Root Cause เกิดขึ้นที่เครื่องใดเครื่องหนึ่งโดยเฉพาะ
🔒 3 การันตีความถูกต้องของโหมด Concat
  1. ลำดับ Node แน่นอน: เครื่อง Node 1 จะแสดงก่อน Node 2 เสมอตามการตั้งค่าคอนฟิก ไม่มีการสลับที่
  2. เรียงจากบนลงล่าง: บรรทัด Log ภายในแต่ละเครื่องจะเรียงลำดับเวลาตามความเป็นจริง ไม่มีการกลับหัว
  3. ป้องกันการกลืนข้อมูล (Fair-share Allocation): ระบบจะจัดสรรโควตาบรรทัดอย่างเป็นธรรม เครื่องที่มี Log มากจะไม่สามารถกลืนกินข้อมูลของเครื่องที่มี Log น้อยจนมองไม่เห็นได้

4. การค้นหาข้อความในโฟลเดอร์ (Search in Folder & Grep)

ในระบบที่มี Log ขนาดใหญ่หรือมีไฟล์ย้อนหลังหลายวัน ผู้ใช้ไม่จำเป็นต้องเปิดหาทีละไฟล์อีกต่อไป! ฟังก์ชัน 🔍 Search in folder จะทำการสแกนหาข้อความที่ต้องการจากทุกไฟล์ในโฟลเดอร์ปัจจุบันทันที (และในโหมด Cluster จะสแกนข้ามทุกโหนดพร้อมกัน):

ขั้นตอนการค้นหาในโฟลเดอร์:

  1. กดปุ่ม 🔍 Search in folder
    ปุ่มนี้อยู่มุมบนขวาของตารางไฟล์ (สามารถกดซ้ำเพื่อเปิด/ปิดแถบค้นหาได้)
  2. พิมพ์ข้อความที่ต้องการค้นหา
    เช่น Transaction ID, Request GUID, หมายเลขบัญชี, เลขสัญญาสินเชื่อ, หรือข้อความ Exception เช่น TimeoutException
  3. เลือกตัวเลือก Regex (หากต้องการ)
    หากต้องการใช้นิพจน์ปกติขั้นสูง เช่น ค้นหารูปแบบบัตรประชาชนหรือไอพีแอดเดรส สามารถติ๊กถูกที่ช่อง Regex ได้
  4. คลิกที่ผลลัพธ์เพื่อไปยังบรรทัดนั้นทันที
    เมื่อระบบแสดงรายการบรรทัดที่พบ สามารถคลิกที่รายการนั้นเพื่อเปิดไฟล์ดังกล่าวและเลื่อนหน้าจอไปยังตำแหน่งบรรทัดนั้นพร้อมเน้นสีไฮไลต์ให้อัตโนมัติ

5. แถบตัวกรองด่วน 1-Click (Quick Filter Presets)

ในขณะที่เปิดอ่านไฟล์ Log ระบบมีแถบตัวกรองด่วนแบบสำเร็จรูป (Quick Filters) ช่วยให้ตัดข้อความที่ไม่เกี่ยวข้องออก และเหลือเฉพาะสิ่งที่น่าสงสัยได้ในคลิกเดียว:

ตัวกรอง (Preset) สิ่งที่ระบบคัดกรอง ประโยชน์สำหรับผู้ใช้
💥 Errors & Exceptions กรองเฉพาะข้อผิดพลาดระดับ Error หรือ Exception จริงๆ (ฉลาดพอที่จะตัด JSON ที่มี "error": null ในระดับ INFO ทิ้ง) หาจุดล้มเหลวของโปรแกรมได้ทันทีโดยไม่ต้องไล่ดูทีละบรรทัด
⚠️ Warnings กรองเฉพาะบรรทัดที่มีข้อความเตือน WARN หรือ Warning ตรวจสอบสัญญาณเตือนก่อนที่ระบบจะเกิดเหตุการณ์วิกฤต
🌐 HTTP 4xx / 5xx กรองเฉพาะบรรทัดที่มีรหัสสถานะ HTTP ผิดพลาด เช่น 400, 401, 404, 500, 502, 503, 504 สืบสวนปัญหาการเชื่อมต่อระหว่าง Microservices หรือ API Gateway
⏱️ Slow Requests (>1s) ตรวจจับและคัดกรองคำขอที่ใช้เวลาประมวลผลนานกว่า 1,000 มิลลิวินาที (1 วินาทีขึ้นไป) ระบุจุดคอขวด (Performance Bottlenecks) ของระบบ
🆔 Trace ID / GUID กรองหาบรรทัดที่มีค่า Correlation ID, RequestId หรือ GUID รูปแบบมาตรฐาน ใช้ติดตามธุรกรรมของลูกค้ารายบุคคลข้ามระบบงาน
🔌 Timeouts & Sockets กรองเฉพาะปัญหา Connection Timeout, Socket Closed, หรือ Connection Refused ตรวจหาสาเหตุเซิร์ฟเวอร์ปลายทางล่มหรือปัญหาทางเน็ตเวิร์ก

6. จัดรูปแบบ JSON และเครื่องมือสืบสวนขั้นสูง

ไฟล์ Log ยุคใหม่มักมีขนาดก้อน JSON Payload ที่ยาวมากและพิมพ์ต่อกันเป็นบรรทัดเดียว ทำให้อ่านยากอย่างยิ่ง MyLog จึงเตรียมเครื่องมือช่วยวิเคราะห์ขั้นสูงไว้รองรับ:

6.1 ระบบจัดรูปแบบ JSON (Auto Format JSON & Expand Toggle)

  • ช่องติ๊ก Auto-Format JSON: เมื่อติ๊กใช้งาน ระบบจะค้นหาก้อน JSON ในข้อความ Log แล้วจัดย่อหน้า (Indentation) ขึ้นบรรทัดใหม่อย่างสวยงามโดยอัตโนมัติ
  • คลิกย่อ-ขยายเฉพาะจุด: บนแต่ละก้อน JSON จะมีปุ่มสำหรับคลิกพับเก็บ (Collapse) หรือกางออก (Expand) ได้อย่างอิสระ

6.2 Request Flow Tracker (สืบเส้นทาง GUID อัตโนมัติ)

ระบบมี AI Tokenizer ทำการตรวจจับรหัส GUID, CorrelationId, และ RequestUid ในทุกบรรทัด Log แล้วแปลงเป็น Clickable Chip:

  • เมื่อคลิกที่ชิปรหัสใดๆ หน้าจอจะเข้าสู่โหมด Flow Tracker ทันที
  • ระบบจะคัดกรองเฉพาะบรรทัดที่เกี่ยวข้องกับคำขอนั้นตั้งแต่เริ่มเข้าสู่ระบบจนเสร็จสิ้นกระบวนการ
  • มีปุ่ม Copy Flow Summary เพื่อคัดลอกขั้นตอนทั้งหมดไปสรุปส่งทีมงานได้ในคลิกเดียว

6.3 ระบบปักหมุดและส่งออกเหตุการณ์ (Bookmarks & Incident Summary)

  • คลิกที่ไอคอนรูปดาว ☆ หน้าเลขบรรทัดเพื่อปักหมุดบรรทัดสำคัญ
  • คลิกเปิด Bookmarks (⭐) เพื่อดูสรุปรายการที่ปักหมุดไว้ทั้งหมด
  • กดปุ่ม Export Summary เพื่อสร้างข้อความรายงานสรุปเหตุการณ์พร้อมนำไปวางใน Microsoft Teams หรือเปิด JIRA Ticket ได้ทันที

7. แดชบอร์ดสรุปสถิติและกราฟ (Analytics Dashboard)

ผู้ใช้สามารถกดปุ่ม 📊 Analytics บนแถบเครื่องมือเพื่อเปิดหน้าต่างวิเคราะห์เชิงลึกของไฟล์ Log ที่กำลังเปิดอยู่:

ประโยชน์ของแดชบอร์ด:

  • การ์ดสรุป KPI: ทราบจำนวนรวมของ Errors, Warnings, Info logs และจำนวนบรรทัดทั้งหมดที่สแกน
  • กราฟการกระจายตัวรายชั่วโมง (Hourly Histogram): มองเห็นได้อย่างชัดเจนว่าระบบเริ่มเกิดปัญหาที่ชั่วโมงใด โดยสามารถคลิกที่แท่งกราฟชั่วโมงนั้นเพื่อกรองดู Log เฉพาะช่วงเวลาดังกล่าวได้ทันที
  • Top Error Patterns: สรุปข้อความ Error ที่เกิดขึ้นซ้ำบ่อยที่สุด พร้อมจำนวนครั้งที่พบ เมื่อคลิกที่รายการ ระบบจะทำการค้นหาข้อความ Error นั้นในหน้าจอ Log ให้อัตโนมัติ

8. การดาวน์โหลดไฟล์และโฟลเดอร์ (Downloads & ZIP)

MyLog มีฟังก์ชันสำเนาและส่งออก Log ออกมาวิเคราะห์ต่อนอกระบบได้อย่างสะดวก รวดเร็ว และประหยัดหน่วยความจำ:

รูปแบบการดาวน์โหลด ตำแหน่งปุ่มคำสั่ง ผลลัพธ์ที่ได้
ดาวน์โหลดไฟล์เดี่ยว ปุ่ม Download ในตารางไฟล์ หรือปุ่ม Download File ในแถบ Viewer ดาวน์โหลดไฟล์ Log นั้นในรูปแบบ .log หรือ .txt แบบต้นฉบับดั้งเดิม
ดาวน์โหลดทั้งโฟลเดอร์ (ZIP) ปุ่ม ⬇ Download ZIP มุมบนขวาของตารางไฟล์ ระบบจะบีบอัดไฟล์ Log ทั้งหมดในโฟลเดอร์เป็นไฟล์ ZIP เดียว (หากอยู่ในโหมด Cluster ระบบจะดึงไฟล์จากทุก Node มารวมแยกโฟลเดอร์ให้เป็นระเบียบ)
ดาวน์โหลดไฟล์รวม Concat (.log) ปุ่ม 📑 Cluster .log ในแถบควบคุมของ Cluster Viewer รวม Log ของทุกโหนดต่อกันเป็นไฟล์ .log เดียว นำไปเปิดดูใน Text Editor ภายนอกได้ทันที

9. การใช้งานบนโทรศัพท์มือถือ (Mobile Field Console)

สำหรับทีมงาน On-call หรือ Support ที่จำเป็นต้องตรวจสอบระบบนอกสถานที่ MyLog มีหน้าจอมือถือ (Field Console UX) ที่ออกแบบมาเพื่อการใช้งานด้วยนิ้วโป้งมือเดียวโดยเฉพาะ:

ฟังก์ชันเด่นบนอุปกรณ์มือถือ:

  • Bottom Command Bar: ปุ่มคำสั่งสำคัญย้ายมาอยู่ชิดขอบล่างหน้าจอ ได้แก่ ปุ่ม 🚨 Errors Only (กรองเฉพาะข้อผิดพลาด), 🔍 Search (ค้นหา), ↩️ Wrap (สลับการตัดบรรทัด) และ ⭐ Bookmarks (ปักหมุด)
  • Mobile Stats Ribbon: แถบสรุปสถานะการเชื่อมต่อ และจำนวน Error/Warning แสดงเด่นชัดที่ส่วนบนของหน้าจอ
  • Tap-to-Inspect Bottom Sheet: แตะที่บรรทัด Log เพื่อเปิดการ์ดแสดงรายละเอียดเชิงลึก พร้อมปุ่มคัดลอก GUID สะดวกสบาย

10. ตัวอย่างสถานการณ์แก้ปัญหาจริง (Practical Scenarios)

สถานการณ์ที่ 1: ตรวจสอบปัญหา Timeout ในระบบหลัง Load Balancer

  1. เลือกโหมด Cluster / LB
    คลิกแถบ Cluster / LB ใน Sidebar ด้านซ้าย และเลือกคลัสเตอร์ที่ต้องการตรวจสอบ
  2. เปิดไฟล์ Log ของวันนี้
    คลิกปุ่ม Open ที่ไฟล์ Log ประจำวัน ระบบจะโหลดหน้าต่างแบบรวมโหนด
  3. คลิกเลือกมุมมอง Concat หรือ Timeline
    คลิกที่ 📑 All Nodes (ต่อกัน / Concat) เพื่อดูว่า Timeout เกิดที่ Node 1 หรือ Node 2
  4. เลือกตัวกรองด่วน Timeouts & Sockets
    ระบบจะกรองตัดบรรทัดปกติออก เหลือเฉพาะบรรทัดที่เกิด Timeout ชี้เป้าปัญหาได้ภายใน 5 วินาที

สถานการณ์ที่ 2: ลูกค้าแจ้งเลขอ้างอิง Transaction ID แต่ไม่ทราบว่าคำขอวิ่งไปเครื่องไหน

  1. เปิดหน้าจอ File Browser ของคลัสเตอร์นั้น
    ไม่ต้องคลิกเปิดทีละไฟล์
  2. คลิกปุ่ม 🔍 Search in folder
    พิมพ์รหัส Transaction ID ลงในช่องค้นหา แล้วกด Enter หรือคลิก Search Folder
  3. ดูผลลัพธ์ที่พบ
    ระบบจะแสดงป้ายกำกับทันทีว่าพบ Transaction ID นี้ในไฟล์ใด และเกิดขึ้นที่ Node 1 หรือ Node 2 พร้อมเลขบรรทัด
  4. คลิกผลลัพธ์เพื่อกระโดดไปยังบรรทัดนั้น
    ระบบจะเปิดไฟล์และเลื่อนไปยังบรรทัดที่พบพร้อมไฮไลต์สีให้อัตโนมัติ

11. คำถามที่พบบ่อยและแนวทางแก้ไข (FAQ)

Q: ทำไมโหมด Cluster บางครั้งขึ้นสถานะ Offline ของบางโหนด?
A: ระบบ MyLog มีการทดสอบการเชื่อมต่อไปยังแต่ละโหนดด้วย Timeout สั้น (2-5 วินาที) หากเครื่องแม่ข่ายปลายทางกำลังรีสตาร์ต ปิดปรับปรุง หรือเครือข่ายขัดข้อง โหนดนั้นจะขึ้น Offline ชั่วคราว แต่โหนดอื่นๆ จะยังคงเปิดดู Log ได้ตามปกติ และเมื่อเครื่องดังกล่าวกลับมาออนไลน์ สถานะจะกลับเป็นปกติโดยอัตโนมัติ
Q: ฟังก์ชัน Folder Search ค้นหาได้ลึกและเร็วแค่ไหน?
A: ระบบจะทำการสแกนไฟล์ .log และ .txt ในโฟลเดอร์ปัจจุบันสูงสุด 20 ไฟล์ล่าสุดของแต่ละโหนด โดยอ่านข้อความแบบสตรีมมิงความเร็วสูง จึงไม่ทำให้เซิร์ฟเวอร์หน่วงและตอบสนองได้ภายในไม่กี่วินาที
Q: ทำไมเปิดดูไฟล์ Log ขนาดหลายร้อยเมกะไบต์แล้วเบราว์เซอร์ไม่ค้าง?
A: MyLog ใช้เทคโนโลยี Virtual DOM Rendering โดยจะเรนเดอร์เฉพาะบรรทัดที่ปรากฏอยู่ในขอบเขตสายตาของผู้ใช้เท่านั้น ทำให้เบราว์เซอร์ไม่ต้องแบกรับ DOM Element นับล้านชิ้น และใช้งานหน่วยความจำอย่างประหยัด
Q: ต้องการพิมพ์คู่มือฉบับนี้เก็บไว้ทำอย่างไร?
A: สามารถกดปุ่ม ⬇ ดาวน์โหลด PDF ที่แถบนำทางด้านบนเพื่อรับไฟล์ PDF สำเร็จรูป หรือกดปุ่ม 🖨️ สั่งพิมพ์เอกสาร เพื่อสั่ง Print ออกเครื่องพิมพ์ของท่านได้ทันที

12. สรุปปุ่มลัดและคำสั่งด่วน (Action Cheat Sheet)

ปุ่ม / ฟังก์ชัน ตำแหน่งบนหน้าจอ การทำงาน

⬇ Download ZIP มุมขวาบนของตารางไฟล์ บีบอัดไฟล์ทั้งโฟลเดอร์เป็น ZIP ก้อนเดียว
📑 All Nodes (Concat) Pill Switcher ใน Cluster Viewer สลับการดู Log รวมแบบต่อกัน Node 1 จบแล้วตามด้วย Node 2
